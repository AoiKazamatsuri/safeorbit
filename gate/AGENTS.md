# gate：检查与门控

本区区分两类检查：默认的队列机械检查，以及 [checks.md](checks.md) 中按项目配置的业务检查。效果评价与趋势分析另住 [eval](../eval/AGENTS.md)。

- 队列检查随工具运行，并由 init 接入 Git 的 pre-commit 与 pre-merge-commit；核对五状态/容量事件重放、配置、任务包/取消档案和实际暂存账本、历史、视图、封存卷、相关交付指纹及运行态排除。检查异常就拒绝提交，不把崩溃当通过。
- 现有 Git 钩子继续运行；不覆盖其内容或跳过其拒绝结果。保护接线异常时工具拒绝写账。
- 项目业务检查不因写在文件里就自动执行，由 Agent 按批准方案实际运行并汇报（[根契约](../AGENTS.md)第 15 条）。
- 调整已批准任务的验收方法，先按任务规则重新确认，不能临时降低标准。
- 本次读数归任务，通过 deliver 登记回执，不把本区改成最新结果账。
- 本区的检查只核对记录、配置与指纹，不验证申报的真实性；机器检查的边界见根契约第 2 条。

## 接入项目自有的提交检查

需要在每次提交时自动运行的项目检查，按下面的方式接，不改队列钩子：

- 检查逻辑写成仓库里的脚本（例如 `tool/<工具>/pre-commit.sh`），随仓库分发；在 [checks.md](checks.md) 登记检查项，在 [tool/catalog.md](../tool/catalog.md) 登记工具。
- 本机接线写进 Git 原来的钩子目录：init 之前没有设置 `core.hooksPath` 时就是 `.git/hooks/`。在那里放 `pre-commit` 与 `pre-merge-commit` 两个薄脚本，调用仓库里的检查脚本，并用 `chmod +x` 设为可执行：队列钩子只调用可执行的原钩子，没有执行权限的会被静默跳过，doctor 也不查。init 装的队列钩子先运行它们，它们拒绝则提交被拒，通过后再做队列检查。装好后故意暂存一处应被拒的改动试提交一次，确认确实拦截。
- 不要改 `core.hooksPath`；改了 doctor 会报保护未就绪。钩子是本机配置，不随仓库分发，每个克隆都要装一次，装法写在该工具的说明里。
- 检查脚本只在暂存改动涉及相关路径时运行，检查暂存内容而不是工作区；需要的运行环境缺失时拒绝提交，不把“没跑”当成“通过”。
- 检查需要第三方依赖时，安装依赖属于须明确授权的动作（根契约第 3 条）；依赖目录写进 `.gitignore`，队列工具保持零依赖。

修改机械工具后运行本区的全部真实集成测试——[队列回归](test_task_queue.py)、[状态包回归](test_state_queue.py)与[编号回归](test_task_numbering.py)，命令见 [checks.md](checks.md)——不以规则文案自证。返回 [根契约](../AGENTS.md)。
