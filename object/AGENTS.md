# object：工作对象

本目录放 SafeOrbit Demo 的全部代码与开发工具。开发依据是三份 truth 文档：产品做成什么样以[产品设计](../truth/产品设计.md)为准，系统怎么搭以[工程架构](../truth/工程架构.md)为准，做到什么程度以[项目目标](../truth/goals.md)为准。代码与这三份文档冲突时，先停下问用户，不在代码里自行改设计；参考资料只作候选（D19）。

## 目录布局

目录布局经用户在任务 [T3](../queue/tasks/T3/goal.md) 中确认。新增顶层目录须经用户同意并改本表；目录骨架由首个开发任务建立，不预建空目录。

| 目录 | 放什么 | 对应工程架构 |
| --- | --- | --- |
| `ios/` | Xcode 工程：SafeOrbit App（老人与家属两种身份）的 Swift 与 SwiftUI 源码、单元测试 | 第 10 节 |
| `server/` | NestJS 后端程序：照护接口、照护智能体、触达网关三个模块；Docker Compose 文件（后端程序与 PostgreSQL 加 PostGIS）；模块边界检查（dependency-cruiser）的规则文件 | 第 6、8、9、11、12 节 |
| `dev/` | 开发工具：历史灌入脚本（生成一个月模拟轨迹，经照护接口按历史时间回放）；Xcode 播放的模拟轨迹文件（WGS-84 坐标），由 Xcode 工程按相对路径引用 | 第 14 节 |

- 后端模块与代码中的名字按工程架构第 3 节“统一命名”。
- 模块之间只经照护接口公开的接口与事件交互，任何模块不得绕过照护接口直接访问数据库（工程架构第 6 节“模块边界”）；由模块边界检查把守。

## 构建、运行与测试

骨架落地前只定原则；具体命令由首个开发任务搭好骨架后补进本节，并在 [gate/checks.md](../gate/checks.md)“项目专属检查”的对应项写成原样命令。

- **iOS**：用 Xcode 打开 `ios/` 下的工程，在真机上运行；命令行构建与单元测试用 `xcodebuild`，单元测试在模拟器上跑。最低系统 iOS 17。
- **后端**：Docker Compose 一键启动后端程序与数据库（工程架构第 14 节）；后端单元测试与模块边界检查在 `server/` 下运行。
- **开发工具**：灌入脚本与模拟轨迹文件的用法，由编写它们的任务补进本节。
- **演示连接**：两部 iPhone 与开发者电脑连同一个 Wi‑Fi，服务器地址写在 App 的构建配置里（工程架构第 6 节）；连接细节以首个开发任务的验证结论为准（工程架构第 15 节）。

终端能跑的构建与测试由 Agent 自己跑，读数写进任务回执（根契约第 15 条）。

## 密钥与本机配置

- 大模型密钥、苹果推送密钥及其他凭据只放本机，经环境变量或本机文件注入，不入库，也不写进文档、任务记录与回执；文档里只写凭据的名称与获取方式（根契约第 4 条）。
- 后端从环境变量读配置；本机值放在 `server/.env`。需要说明有哪些变量时，提交一份只有变量名、不含真实值的 `.env.example`。
- 苹果推送密钥是 `.p8` 文件，放在仓库外，或放在仓库内但不提交。

## 忽略的目录与文件

下列条目写在仓库根的 [.gitignore](../.gitignore)“工作对象”一段，两处保持一致；新增生成目录或本机密钥文件时两处一起改。

| 条目 | 是什么 |
| --- | --- |
| `DerivedData/`、`xcuserdata/`、`.build/` | Xcode 与 Swift 包的构建产物、个人工程设置 |
| `node_modules/`、`dist/`、`coverage/` | Node 依赖、构建产物与测试覆盖率报告 |
| `.env`、`.env.*`（`.env.example` 除外） | 本机环境变量 |
| `*.p8` | 苹果推送密钥 |

## 依赖

- 依赖装在各部分自己的目录里：用 Node 的部分各有自己的 `package.json` 与锁文件，锁文件入库；iOS 用 Swift Package Manager，解析结果 `Package.resolved` 入库。
- 已批准并领取的开发任务内，把 npm 包、Swift 包装进项目目录不逐次请示，新增或变更的依赖在回执列明；全局安装、付费服务、账号与证书操作仍逐项请示（根契约第 23 条）。
- 工程架构已定的技术（SwiftUI、NestJS、Vercel AI SDK、PostgreSQL 加 PostGIS、dependency-cruiser）不自行替换；要换先问用户。

## 施工规矩

- 在本目录施工须属于已批准并领取的任务，遵守任务允许修改的范围；本契约不是额外授权。
- 任务、决定、交接与验证回执归[任务区](../queue/AGENTS.md)；本目录只放工作产物，不另建一套治理记录。
- 交付时在任务中引用实际产物（相对仓库根的路径，如 `object/server/…`），不为记录交付而移动对象或复制大文件进任务卷。
