# 任务驱动的项目模板

用户专注任务，Agent 负责执行，程序维护队列。项目要求仍是 Markdown；任务账由本地工具维护，并自动生成可读的任务文件。

**不是完整产品运行时：没有新界面、常驻服务、联网调用或自动派发。** 需要 Python 3.10+ 与 Git，不需要第三方 Python 包。接入与命令操作由 Agent 完成，用户无需手工维护状态。

本 README 面向“怎么用这个模板”。项目接入后，README 可以整份换成项目自己的介绍：Agent 的规则、地图与命令都在[根契约](AGENTS.md)里，任务规则在 [queue/AGENTS.md](queue/AGENTS.md)，队列工具保证什么、不保证什么在 [tool/AGENTS.md](tool/AGENTS.md)。

## 开始使用

1. 克隆模板，或按下节合入已有项目。克隆后把 `origin` 改成项目自己的远端或移除，不把模板仓当作项目的推送目标。
2. 让 Agent 读[根契约](AGENTS.md)，按用户确认填写其中的“身份”表、[工作对象契约](object/AGENTS.md)与[项目目标](truth/goals.md)，并删去根契约文首“维护模板本身”一段。需要常驻的规则写进根契约或对应区契约，不另填接入表；用户已明确的范围不重复请批。模板本身不提供施工授权。同时对照 [tool/catalog.md](tool/catalog.md)“可选工具”逐项问用户是否需要，例如需要维护架构图的项目可启用随模板提供的制图工具。
3. Agent 检查 Python 与 Git，并在模板根执行 `python3 tool/shell.py init`，然后执行 `python3 tool/shell.py doctor`。只有报告 `protection: ready` 且 `protocol: 2` 才表示队列接线已就绪。macOS 自带的 `python3` 是 3.9，须改用 3.10 以上的解释器。init 会记下运行它的解释器路径，此后所有队列命令都要用同一个路径运行，详见根契约第 4.6 节。
4. Agent 经 `python3 tool/shell.py state get` 获取并读取完整状态包：仅包含白名单 truth 文件全文和窗口内任务包文件全文。每次受控写入使用自己的状态版本，过期就重新获取并读变化。
5. Agent 按 [方案模板](queue/templates/task.md) 起草，使用队列工具登记。用户已说“按此方案实施”时，直接记录这条指令并进入批准执行，不重复请批。
6. Agent 领取、执行、实测、交付；用户通过后记录验收通过并封存。具体命令与恢复办法见 [工具用法](tool/queue-usage.md)。

克隆不会自动安装 Git 钩子，所以每个新克隆都须接入一次；Agent 可以代做。工具不擅自安装 Python、不创建远端或发布。缺运行条件时明确报“保护未就绪”，不静默退化为人工记账。项目有远端或多个克隆时，约定一个写账主仓，见[工具用法](tool/queue-usage.md)“多个克隆与远端”。

## 放进已有项目

先在项目外检查模板，再逐项合入，不整目录覆盖。已有 README、AGENTS.md、.gitignore、LICENSE 与 NOTICE 均保留；入口人工合并，有冲突先请用户决定。原有 Git 钩子会通过接线保留，不直接替换其内容。

同名目录职责冲突时，可将整套模板放入无冲突子目录，在项目原入口链接到模板 AGENTS.md。一个 Git 工作仓只接一套队列；项目位置相对模板根填写，交付工件路径则相对 **Git 仓库根**。现有源码不用搬家。

已有 v1 机器账时，先 `upgrade --preview`，明确确认后追加升级事件；不重写旧历史，旧封卷保持原址与字节。已有旧 Markdown 任务时，先执行 `migrate --preview`。当前仅自动导入无附件、未认领的候裁任务；已批准、终态或复杂历史会明确拒绝，不能凭散文猜授权。迁移会核对预检指纹并保存原件，详见工具用法。

## 从模板同步更新

模板按发布日期标版本，变化写在[变更记录](CHANGELOG.md)。项目在根契约“身份”表记下所基于的版本，在 [tool/AGENTS.md](tool/AGENTS.md)“与模板的差异”登记自己对机制性文件的改动。跟进新版本时，在项目里作为一件任务进行：

1. 在项目外取得模板新版本，读晚于本项目所记版本的变更条目，列出要合入的项。
2. 队列工具（tool/ 下五个 .py）整套替换，不单换其中一件；再按“与模板的差异”清单重放本项目的改动。gate 下的测试、queue-usage.md 与 queue/templates/ 同样处理。
3. 契约文档逐段人工合并，不整文件覆盖：保留项目填写的身份、地图、规则选择与项目专属内容，吸收模板新增或修正的条文。根契约规则编号保持与模板一致，项目新增的规则接在末尾。
4. 运行 gate 中的全部测试，再在写账主仓运行 `doctor` 与 `task status`：doctor 会重放整本机器账，能读通即能接续，旧账不改写。确需试写的，只在临时克隆里做，做完丢弃，不提交、不推送。
5. 同批提交工具、契约与“身份”表里更新后的模板版本。

## 维护验证

修改队列工具后执行 `python3 -B -m unittest discover -s gate -p 'test_*.py' -v`，约 3 分钟。测试创建临时 Git 仓，实际跑命令、并发进程、提交钩子与中断恢复，不改当前实例账。业务提交不会全跑这套开发测试。

在模板源仓本身维护模板时，不运行 init、不登记任务，也不提交 `.shell/`：源仓不带机器账，init 生成的任务账会随提交分发给之后的每个新项目。每次发布在[变更记录](CHANGELOG.md)加一条，写明对实例的影响与同步时要注意的事。
