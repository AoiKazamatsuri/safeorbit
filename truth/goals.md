## 要解决的问题

轻度认知障碍的老人大多还能用智能手机、独立出门，日常路线也相对固定，但偶尔会迷失方向、徘徊，或者找不到回家的路。家属担心他们的安全，却没法一直盯着位置，也难以判断什么时候该介入。

SafeOrbit 让老人的 iPhone 在后台持续记录出行，在异常升级之前发现问题并适度帮助：先引导老人自己回家，风险升高时再请家属介入。目标是兼顾老人的安全与自主出行能力，同时减轻家属持续查看位置、判断风险的负担。

## Demo 阶段：课堂演示与演示视频

状态：已确认。

### 当前交付目标

本阶段专注 Demo App 的开发，做到 Demo 级，用于课堂演示；演示视频由外景实拍与真机录屏剪辑而成，汇报时播放（D1、D37，任务 [T37](../queue/tasks/T37/goal.md)）。交付物有三样：

1. **可真机运行的 Demo**：一个 iPhone App，按老人或家属身份切换界面，界面为英文，中文未做（任务 [T36](../queue/tasks/T36/goal.md)、T47）；后端在开发者自己的电脑上运行（D3、D15）。
2. **一段演示视频**：外景只拍演员；App 画面由两部 iPhone 在室内实际运行录屏（老人手机播放模拟轨迹），剪辑时插入外景。在中国大陆录制，展示下文“完成的判断”中的各个场景（D2、D37，任务 [T37](../queue/tasks/T37/goal.md)）。
3. **两版架构**：放进 PPT 的完整版，与实际开发用的、由完整版简化而来的 Demo 版，写在[工程架构](工程架构.md)中（D1）。

### 完成的判断

演示视频中每个场景的 App 画面都由 Demo 在真机上实际运行、录屏得出，不使用拼接的假界面；外景镜头与录屏只做画面拼接，不往 App 画面上叠加任何界面元素（任务 [T37](../queue/tasks/T37/goal.md)）。场景清单（D40；“绑定”一行由任务 T37 删去）：

| 场景 | 应能看到的结果 |
| --- | --- |
| 安全区 | 家属在地图上添加带标签和半径的安全区 |
| 正常出行 | 老人从家去市场再回家；家属端实时看到位置与轨迹，状态为正常；记录里多出一次“家-市场-家” |
| 低风险 | 老人徘徊达到低风险：老人手机自动语音导航回家，家属收到普通通知，地图状态变黄并写明原因 |
| 高风险 | 异常继续：家属手机收到强提醒，点开事件页，一键呼叫老人 |
| 风险解除 | 老人回到熟悉路线或到家后，状态回到正常，这次风险记为已解除 |
| 老人主动求助 | 老人点“回家”开始语音导航；点“联系家人”拨打家属 |
| 出行记录 | 月历按每天最高风险着色；查看本周记录与一次出行的轨迹和时间线 |
| 趋势 | 路线偏离趋势与四项指标（任务 [T45](../queue/tasks/T45/goal.md)） |
| 智能对话 | 家属问“上次高风险发生了什么”，智能体查数据后作答，引用可核对，不做医学诊断 |
| 双语 | 家属端在中文与英文之间切换（第一次录制不含：Demo 界面只有英文，任务 T36、T47） |

确认方式：

- 执行者在每个开发任务中实跑验证，包括自动化测试与用模拟轨迹回放的场景，读数写进任务回执。
- 用户亲自观看最终录屏视频，判断是否满足演示要求；视频是否合格由用户决定。

### 范围与限制

本阶段做：

- iPhone App（老人与家属两种身份）、单一后端程序与数据库、高德地图、可替换的云端大模型（D3、D16、D17；地图由任务 [T37](../queue/tasks/T37/goal.md) 改为高德）。
- 苹果推送：低风险普通通知与高风险强提醒（D8）。
- 开发与演示所需的工具：按历史时间回放一个月模拟轨迹的灌入脚本、Xcode 播放的模拟轨迹文件（D14、D41）。

本阶段不做：

- 安卓与网页客户端（D3）；App 内的演示模式（D1）；老人端的看护状态显示与相关操作（D11）；服务器自动外呼，只画进完整版（D8）。
- 账号与绑定：Demo 不做登录、注册与扫码绑定，服务器预置一户人家（一位老人、一位家属）（任务 [T37](../queue/tasks/T37/goal.md)）。
- 医学诊断（源自设计说明文档）。
- 两端 App 内通话；跌倒检测、手表与其他传感器；离线地图；周报与月报；上架应用商店、真实家庭试点与相应的合规认证（D33）。

必须遵守的约束：

- 风险判定只由固定规则完成，大模型只负责理解与表达（D4）。
- 在中国大陆录制，地图须处理国内坐标偏移，大模型须在当地可稳定访问（D2、D17）。
- 参考资料仅供参考，其中的具体数字、接口与表结构只作候选（D19）。

## 落地阶段：内部测试版

状态：已确认，以任务 T47 通过为准。

### 目的

让产品离开开发者的电脑和室内录屏，在真实的室外出行中跑起来：检验后台监测、风险判断、提醒送达与回家导航在真实条件下是否可靠，用真实轨迹校准风险阈值；也为以后用真机在室外实时运行、拍摄更真实的演示视频打下基础。本阶段只供内部测试团队使用，不面向公众，也不追求大规模用户。Demo 阶段的录制照常进行，不受本阶段影响。

### 交付目标

1. **可安装的内部测试版 App**：经苹果 TestFlight 的内部测试分发，测试者为开发者团队成员（苹果规定内部测试最多 100 人，不需要测试版审核）。推送改用苹果的正式通道。
2. **云端后端**：一台云服务器，经域名与加密连接（HTTPS）访问，不再依赖开发者电脑与同一 Wi‑Fi；数据库定期备份，出错能被发现。
3. **多户使用**：每户一位老人、一位或多位家属。家属新建家庭后，老人手机与其他家属用邀请码或二维码加入；各户数据互相隔离，未加入家庭的手机取不到任何数据。
4. **内部测试说明**：安装、加入家庭、授权、出门测试、反馈问题与退出测试的步骤。

### 完成的判断

测试团队至少 3 户、每户连续 7 天在室外真实出行中使用。测试者两人一组：一人带“老人手机”出门，一人用“家属手机”。以下各项都能在真实使用中看到：

| 项目 | 应能看到的结果 |
| --- | --- |
| 安装与加入 | 测试者从 TestFlight 安装；家属新建家庭，老人手机经邀请码或扫码加入；全程不需要开发者电脑参与 |
| 户间隔离 | 一户的家属看不到其他户的任何数据；未加入家庭的手机取不到数据 |
| 后台监测 | 老人手机锁屏、放在口袋里也持续上报；App 被关闭或手机重启后自动恢复上报；每天的耗电记录在测试记录里，目标值在首轮实测后确定，写进测试说明 |
| 监测中断提醒 | 老人手机关闭定位或精确位置、离线、没电时，家属收到“监测受限”通知 |
| 真实提醒 | 室外出行中达到低风险、高风险时，家属手机收到普通通知与强提醒，点开进入对应页面；推送失败会重试 |
| 自动回家导航 | 老人手机在前台、后台与锁屏时都能自动开始语音导航；做不到时后备通知出现，点开即开始导航 |
| Demo 阶段场景 | Demo 阶段的场景（双语除外）都能在室外真机实时运行中复现，不依赖模拟轨迹 |
| 阈值校准 | 先经一段只记录、不提醒的试运行，按真实轨迹调整风险阈值；调整前后的误报与漏报情况写进任务回执 |

确认方式：

- 执行者在开发任务中跑自动化测试与真机实跑，读数写进任务回执。
- 测试团队按测试说明实际使用并反馈；是否达到内部测试可用由用户决定。

### 范围与限制

本阶段做：

- Demo 阶段的全部功能，迁到云端后端与多户使用。
- 简单的家庭与成员：新建家庭、邀请码或二维码加入、退出与移除成员；不做 Apple 账号或手机号登录。
- 老人手机的可靠后台监测：在家用低功耗方式，外出提高精度；被关闭或重启后自动恢复；“监测受限”提醒（产品设计第 3.3 节）。
- 推送改用正式通道，失败重试；内部测试版的发布流程。
- 首次使用时展示隐私说明并取得同意，包括地图服务要求的隐私确认；测试者可以删除自己家庭的数据。
- 保留“预置一户人家并回放一个月模拟历史”的初始化方式，供以后录制演示使用。

本阶段暂不做：

- 真实的认知障碍老人参与测试；TestFlight 对外测试与上架应用商店；相应的合规认证。
- 中文界面：沿用英文，中文在真实老人参与前单独补做。
- 老人端适老化；真实路线学习与目的地推断（任务 [T44](../queue/tasks/T44/goal.md)）；长时间停留、来回折返两类异常。
- 服务器自动外呼；一位家属关注多位老人；实时长连接（沿用定时刷新）。
- Demo 阶段“本阶段不做”中的其余各项，除“账号与绑定”外照旧不做。

必须遵守的约束：

- Demo 阶段的三条约束照旧适用。
- 测试者都是知情的团队成员，以测试为目的使用；App 不作为真实照护的依据。
- 位置与轨迹只用于本项目测试。测试结束后由主要照护者在 App 里删除整个家庭的数据；未删除的，测试结束 30 天后由开发者统一清除。
- 服务器部署在中国大陆，域名按要求备案。
- 密钥只放服务器与开发者本机的环境配置，不入库（根契约第 4 条）。
- 大模型维持零费用，免费额度用完即停。

前提（由用户办理，开发任务开工前就绪）：付费苹果开发者账号；云服务器与域名；高德地图密钥的使用额度满足测试需要。

## 已定的方向

以下决定记录在任务 [T2](../queue/tasks/T2/goal.md) 的批准基线中，注明任务 [T37](../queue/tasks/T37/goal.md)、[T47](../queue/tasks/T47/goal.md) 的条目由该任务修订或新增：

- Demo 阶段做到 Demo 级，用于课堂演示与演示视频；架构分 PPT 完整版与开发用 Demo 版（D1）。落地阶段做到内部测试可用，只供测试团队使用（任务 T47）。
- 界面中英双语，在中国大陆录制演示（D2）。Demo 与内部测试版暂只有英文，中文在真实老人参与前单独补做（任务 T47）。
- 一个 iPhone App，按老人或家属身份切换（D3）。
- 规则管判断，大模型管理解与表达；给老人的提醒语用固定模板（D4、D5）。
- 高风险联络：Demo 用强提醒加一键呼叫，完整版另加服务器自动外呼（D8）。内部测试版同 Demo（任务 T47）。
- 偏离参照先用“家 ↔ 各安全区”的地图规划路线，积累正常出行后改用常走路线（D9）。
- 老人端不显示被看护状态，也不可操作（D11）。
- 灌入一个月模拟历史（经后端按历史时间回放），风险场景用模拟轨迹演示；演示视频由外景实拍与真机录屏剪辑而成（D14、D37、D41，任务 T37）。
- Demo 部署在开发者电脑上，后端合成一个程序、模块边界由检查把守（D15、D16）。内部测试版仍是一个后端程序，部署到云服务器（任务 T47）。
- Demo 不做账号与绑定，服务器预置一户人家；家属端定时刷新，不建长连接（任务 T37）。内部测试版做家庭与邀请加入，不做账号登录，仍定时刷新（任务 T47）。
- 地图用高德地图，大模型供应商可替换（D17；地图由任务 T37 改定）。大模型现用通义千问 qwen3.7-flash，经兼容接口接入（任务 [T40](../queue/tasks/T40/goal.md)、T47）。
- PPT 架构图按工程架构第 13 节的修订清单全部照改（D18、D38）。
- 风险分三级，徘徊 7 分钟进入低风险、15 分钟进入高风险，低风险即通知家属（D21–D23）。
- 家属端三个底部标签加头像抽屉，新做事件页；老人端精简（D26、D27、D30）。
