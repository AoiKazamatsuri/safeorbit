## 要解决的问题

轻度认知障碍的老人大多还能用智能手机、独立出门，日常路线也相对固定，但偶尔会迷失方向、徘徊，或者找不到回家的路。家属担心他们的安全，却没法一直盯着位置，也难以判断什么时候该介入。

SafeOrbit 让老人的 iPhone 在后台持续记录出行，在异常升级之前发现问题并适度帮助：先引导老人自己回家，风险升高时再请家属介入。目标是兼顾老人的安全与自主出行能力，同时减轻家属持续查看位置、判断风险的负担。

## 当前交付目标

本阶段专注 Demo App 的开发，做到 Demo 级，用于课堂演示；演示视频就是录屏 App，汇报时播放（D1、D37）。交付物有三样：

1. **可真机运行的 Demo**：一个 iPhone App，按老人或家属身份切换界面，中英双语；后端在开发者自己的电脑上运行（D2、D3、D15）。
2. **一段演示视频**：录屏 App，在中国大陆录制，展示下文“完成的判断”中的各个场景（D2、D37）。
3. **两版架构**：放进 PPT 的完整版，与实际开发用的、由完整版简化而来的 Demo 版，写在[工程架构](工程架构.md)中（D1）。

## 完成的判断

演示视频中的每个场景都由 Demo 在真机上实际运行、录屏得出，不使用拼接的假界面。场景清单（D40）：

| 场景 | 应能看到的结果 |
| --- | --- |
| 绑定 | 家属建立老人档案，老人手机扫码完成绑定 |
| 安全区 | 家属在地图上添加带标签和半径的安全区 |
| 正常出行 | 老人从家去市场再回家；家属端实时看到位置与轨迹，状态为正常；记录里多出一次“家-市场-家” |
| 低风险 | 老人徘徊达到低风险：老人手机自动语音导航回家，家属收到普通通知，地图状态变黄并写明原因 |
| 高风险 | 异常继续：家属手机收到强提醒，点开事件页，一键呼叫老人 |
| 风险解除 | 老人回到熟悉路线或到家后，状态回到正常，这次风险记为已解除 |
| 老人主动求助 | 老人点“回家”开始语音导航；点“联系家人”拨打家属 |
| 出行记录 | 月历按每天最高风险着色；查看本周记录与一次出行的轨迹和时间线 |
| 趋势 | 偏离趋势与各项指标，以及智能体写的出行规律描述 |
| 智能对话 | 家属问“上次高风险发生了什么”，智能体查数据后作答，引用可核对，不做医学诊断 |
| 双语 | 家属端在中文与英文之间切换 |

确认方式：

- 执行者在每个开发任务中实跑验证，包括自动化测试与用模拟轨迹回放的场景，读数写进任务回执。
- 用户亲自观看最终录屏视频，判断是否满足演示要求；视频是否合格由用户决定。

## 范围与限制

本阶段做：

- iPhone App（老人与家属两种身份）、单一后端程序与数据库、苹果地图、可替换的云端大模型（D3、D16、D17）。
- 苹果推送：低风险普通通知与高风险强提醒（D8）。
- 开发与演示所需的工具：按历史时间回放一个月模拟轨迹的灌入脚本、Xcode 播放的模拟轨迹文件（D14、D41）。

本阶段不做：

- 安卓与网页客户端（D3）；App 内的演示模式（D1）；老人端的看护状态显示与相关操作（D11）；服务器自动外呼，只画进完整版（D8）。
- 医学诊断（源自设计说明文档）。
- 两端 App 内通话；跌倒检测、手表与其他传感器；离线地图；周报与月报；上架应用商店、真实家庭试点与相应的合规认证（D33）。

必须遵守的约束：

- 风险判定只由固定规则完成，大模型只负责理解与表达（D4）。
- 在中国大陆录制，地图须处理国内坐标偏移，大模型须在当地可稳定访问（D2、D17）。
- 参考资料仅供参考，其中的具体数字、接口与表结构只作候选（D19）。

## 已定的方向

以下决定记录在任务 [T2](../queue/tasks/T2/goal.md) 的批准基线中：

- 项目做到 Demo 级，用于课堂演示与演示视频；架构分 PPT 完整版与开发用 Demo 版（D1）。
- 界面中英双语，在中国大陆录制演示（D2）。
- 一个 iPhone App，按老人或家属身份切换（D3）。
- 规则管判断，大模型管理解与表达；给老人的提醒语用固定模板（D4、D5）。
- 高风险联络：Demo 用强提醒加一键呼叫，完整版另加服务器自动外呼（D8）。
- 偏离参照先用“家 ↔ 各安全区”的地图规划路线，积累正常出行后改用常走路线（D9）。
- 老人端不显示被看护状态，也不可操作（D11）。
- 灌入一个月模拟历史（经后端按历史时间回放），风险场景用模拟轨迹演示；演示视频就是录屏 App（D14、D37、D41）。
- Demo 部署在开发者电脑上，后端合成一个程序、模块边界由检查把守（D15、D16）。
- 地图用苹果地图，大模型供应商可替换、暂不定（D17）。
- PPT 架构图按工程架构第 13 节的修订清单全部照改（D18、D38）。
- 风险分三级，徘徊 7 分钟进入低风险、15 分钟进入高风险，低风险即通知家属（D21–D23）。
- 家属端三个底部标签加头像抽屉，新做事件页；老人端精简（D26、D27、D30）。
- 大模型供应商留到开发接入时再定（D39）。
