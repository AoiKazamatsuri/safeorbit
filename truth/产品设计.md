## 1 定位与原则

SafeOrbit 是一个 iPhone App，帮助轻度认知障碍、仍能独立出门的老人安全自主出行，同时减轻家属持续查看位置、判断风险的负担。它在老人出行出现异常时及早发现，按风险轻重分级帮助：先帮老人自己回家，必要时再请家属介入。

设计原则：

1. **后台自动监测**：老人不用开始或结束任何行程，App 在后台自动记录与判断。
2. **渐进式干预**：帮助力度随风险升高；低风险兼顾老人自助与家属知情，高风险加强家属介入。
3. **人机协同**：智能体负责监测、判断与辅助，重要风险由家属处理。
4. **不限制出门**：安全区是“熟悉地点”，不是围栏；离开安全区本身不算异常（D10、D24）。
5. **老人少操作、少决策**：老人端只留最必要的入口，不显示被看护状态，也不提供相关操作（D11）。
6. **只描述行为，不做医学诊断**：智能体的一切解释只说行为数据及其变化。

## 2 用户与角色

| 角色 | 说明 |
| --- | --- |
| 老人 | 轻度认知障碍，能用智能手机、能独立出门，活动与路线相对稳定；可能偶发迷失方向、徘徊、找不到回家的路，不适合复杂操作 |
| 家属 | 关注老人出行安全，但无法一直盯着位置；希望出事时及时知道、自己判断是否介入 |
| 主要照护者 | 家属中的一位；老人端“联系家人”拨打的对象，完整版自动外呼的对象 |

同一个 App 按身份切换界面：老人身份与家属身份（D3）。

人数关系（D13、D32）：Demo 只支持一位老人；一位老人可以有多位家属，其中一位是主要照护者；一位家属只关注一位老人。完整版允许一位家属关注多位老人。

## 3 核心机制

### 3.1 出行识别

- 老人离开“家”这个安全区、并确实走出一段距离，系统自动开始记录一次出行；回到家并停稳后自动结束。
- 出行按途经的安全区标签命名，如“家-市场-家”；途经未登记的地点记为“外出”。
- 首次启用时老人已在外面，就从当时开始记录，起点标“未知”，不编造离家时间。

### 3.2 异常行为

每类异常都要求持续一段时间才算数，不因一次停留或一次掉头就认定异常。

| 异常 | 含义 | 何时可用 |
| --- | --- | --- |
| 徘徊 | 走了很长的路，净位移却很小，并持续一段时间 | 第一天即可 |
| 长时间停留 | 在安全区以外的陌生地点长时间不动 | 第一天即可 |
| 来回折返 | 短时间内在同一段路上反复往返 | 第一天即可 |
| 偏离路线 | 明显偏离参照路线并持续一段时间 | 见下文“偏离的参照” |
| 异常移动模式 | 时段、频率等与老人的日常规律明显不同 | 只在完整版；Demo 不做（D25） |

**偏离的参照**（D9）：

1. 起步：家属设好安全区后，家属手机用苹果地图算出“家 ↔ 各安全区”的步行路线并上传，先拿它当参照。
2. 学习：每完成一次全程无风险的正常出行，就把这条轨迹叠进“常走路线”；同一条路线攒够 5 次后，改用真实轨迹叠出的常走路线作参照（D22）。
3. 不学异常：出过风险的出行不学入，避免把异常当成习惯。
4. 积累期间，家属端的智能体状态显示学习进度，如“正在熟悉日常路线（已记录 3/5 次）”。

下文的“参照路线”指当时生效的参照：学会之前是起步规划路线，学会之后是常走路线。

### 3.3 风险等级

三级，配色与界面 02–04 一致（D6、D21）：

| 等级 | 英文 | 颜色 | 含义 |
| --- | --- | --- | --- |
| 正常 | Normal | 绿 | 没有异常，或异常尚未持续到足以判断 |
| 低风险 | Warning | 黄 | 某类异常已持续一段时间，老人可能需要帮助 |
| 高风险 | High Risk | 红 | 低风险后异常仍在持续，需要家属介入 |

- 不设“中风险”。
- 高风险成立后，不会因为几个正常的定位点就降回低风险，只能整体解除。
- “风险解除”是一次事件，不是第四种等级：解除后回到正常，这次风险作为一条记录保存，标“已解除”。
- 出行途中定位中断（老人关了定位或“精确位置”、手机离线或没电）时，另挂一个“监测受限”标记。它不算风险等级：既不当作有风险，也不当作正常，更不据此解除已有风险。老人在家时手机本来就很少上报位置，不据此判为监测受限。
- 判定时间（D22）：持续时间从异常开始算起；徘徊持续 7 分钟进入低风险、15 分钟进入高风险。其他异常的时长、距离等阈值见[工程架构](工程架构.md)第 8 节，均为可配置的 Demo 默认值。

### 3.4 分级帮助

| 等级 | 老人手机 | 家属手机 |
| --- | --- | --- |
| 正常 | 不打扰 | 地图正常显示，不推送 |
| 低风险 | 自动开启语音导航回家（界面 12）：先播一句固定模板的提醒（D5），之后由导航播报转向 | 立即收到一条普通通知，如“徘徊 7 分钟，正在为她开启回家导航”（D7、D23）；地图状态变黄并显示原因 |
| 高风险 | 继续语音导航 | Demo：收到能穿透专注模式（含勿扰）的强提醒，点开即事件页，可一键呼叫老人。完整版：服务器再自动拨打主要照护者的手机（D8） |
| 解除 | 结束导航提示 | 收到解除通知，地图回到正常 |

- 固定模板只填称呼与地点，例如“奶奶，我们回家吧”；“前方 80 米右转”一类转向指令由导航生成。中英文各一套。
- 事件页见第 5.3 节。
- 同一次风险不会因为每次上报位置而重复提醒。

### 3.5 风险解除

满足以下任一条件，风险解除：

- 老人回到家，或回到参照路线上，并持续正常 3 分钟（D22）；
- 家属在事件页点“确认已会合”。即使老人手机此时离线，也能解除。

以下情况都不会解除风险：只是接了电话、只是看了通知、定位暂时中断。

### 3.6 智能体

用户看到的智能体是一个以第一人称说话的看护角色，会监测、出手、解释，例如“我先提醒她回家；她继续走远，我就提升了风险等级并通知了你”（D4）。内部分工两版一致：

| 环节 | 由谁完成 |
| --- | --- |
| 识别异常行为、判定风险等级、决定出手动作 | 固定规则，每次结果可复现 |
| 回答家属提问（智能对话） | 大模型：先查数据，再组织回答 |
| 风险事件的解释与摘要（为什么判为低风险、经过如何） | 大模型 |
| 出行规律描述（趋势页上的一段话） | 规律由程序统计，大模型写成人话 |
| 对老人说的提醒语 | 固定模板（D5），不经大模型 |

智能体状态显示在家属端位置页人物卡的姓名下方一行（D27）：监测中、正在熟悉日常路线（附进度）、监测受限（附原因）。

## 4 老人端

老人端没有底部标签（D12、D26），也不显示任何被看护状态（D11）。

| 界面 | 内容 |
| --- | --- |
| 地图（界面 10） | 全屏地图，显示老人当前位置与“家”等安全区图标；底部两个大按钮“回家”（Go Home）、“联系家人”（Call Family）；左上角为老人头像，点开精简设置 |
| 导航回家（界面 12） | 地图上画出回家路线；底部指示卡显示下一步转向、距离、目的地与预计时间，如“前方 80 米右转 · 回家 · 7 分钟”；右侧为语音播报开关；下方保留“联系家人”；另有“结束导航”按钮 |
| 呼叫家人（界面 11） | 点“联系家人”后先显示呼叫卡片“正在呼叫你的家人 / 我们会保护你的安全”，随后由 iPhone 系统电话接管，系统会先请老人确认（D30） |
| 精简设置 | 姓名与头像（只读）、语音音量（D30）；不提供关闭定位或监测的入口 |

- “回家”：老人主动点击时开始语音导航回家，与低风险时自动开启的导航相同。
- “联系家人”：拨打主要照护者的手机（D8）。
- “结束导航”：点后需再确认一次；结束导航不影响风险状态，家属照常知情（D30）。
- 老人手机的界面语言跟随系统语言（D30）。

## 5 家属端

### 5.1 导航结构

底部浮动标签栏三个纯图标：位置、智能体、记录；“我的”收进左上角头像打开的侧边抽屉（界面 01）（D12、D26）。

### 5.2 位置（界面 02–04）

- 全屏地图：老人实时位置与朝向、本次出行轨迹、安全区图标。
- 位置上方的气泡写当前状态：在家、在某安全区、“前往市场”（沿参照路线朝某个安全区移动时）、“外出中”；有风险时写异常与持续时间，如“徘徊 7 分钟”，并按等级变色。
- 底部人物卡：老人头像与姓名、姓名下方的智能体状态、风险等级胶囊、老人手机电量（随位置一起上报）、当前地址、“呼叫”圆钮（颜色随等级变化，高风险带光环；由系统确认后拨出）、“导航前往”按钮（交给苹果地图规划去老人所在位置的步行路线）。
- 点人物卡或风险气泡进入事件页（第 5.3 节）。
- 右侧悬浮按钮：智能体入口、新增安全区、刷新定位。智能体入口是快捷方式，点了切到底部“智能体”标签（D26）。

### 5.3 事件页

事件页是新增界面，设计图中没有，需要新做（D27）。

- 入口：点高风险强提醒；或在位置页点人物卡、风险气泡。
- 内容：地图上的老人当前位置与本次轨迹；风险等级、异常行为与持续时间；智能体写的经过与原因（大模型生成，可能稍后出现）；已执行的帮助，如“回家导航已开始”或“导航未能开始”。
- 动作：“呼叫老人”“导航前往”“确认已会合”。风险解除后可“标为误报”，误报不计入日历与趋势。

### 5.4 新增安全区（界面 06）

- 在地图上选点或搜索地址；选择标签（家、市场、医院，或新建标签）；选择半径（100 米、200 米、500 米、1 公里、2 公里，D28）；“创建安全区”或“取消”。
- 必须有一个“家”（D10）。
- 安全区的作用：作为熟悉地点，区内久停不算异常；给出行命名；创建时由家属手机规划“家 ↔ 该安全区”的步行路线，作为偏离检测的起步参照（第 3.2 节）。

### 5.5 智能体（界面 05）

- 对话页是“智能体”标签的一级页面，不带设计图 05 左上的“返回”（D26）。
- 家属用文字或语音提问，例如“上次走失是什么时候？”“最近徘徊是不是变多了？”。
- 智能体先查数据，再用第一人称回答，回答中的日期、次数与记录可核对；“最近”这类模糊时间会换成明确的日期范围写在回答里。回答先整段生成、核对后再分段显示，所以会比逐字输出稍慢。
- 只描述行为及其变化，不做医学诊断；问到病情时说明边界。
- 用提问的语言作答（中文或英文）。
- 输入栏左侧为语音输入；右侧“+”号打开常用问题快捷入口，如“今天出门了吗”“最近徘徊多吗”（D28）。

### 5.6 记录：数据（界面 07、08）

页面上方用“趋势 / 数据”切换。数据页包括：

- **月历**：按老人所在时区的自然日着色，取当天最高风险：绿＝出行且无风险，黄＝最高为低风险，红＝最高为高风险；当天没出行不着色；当天出行中定位缺失较多时，日期外加灰色虚线圈，表示“记录不完整”（D28）。已解除的风险仍按当天最高等级着色；被标为误报的不计入。
- **本周记录**：按日列出出行，每行显示日期、风险胶囊、出行名称（如“家-市场-家”）、异常类型（如“路线偏离”）、出行时长（如“1 小时 20 分”，D28）；可切换上一周、下一周，“查看更多”展开整周。风险胶囊按三级显示，设计图只画了 Risk、Normal 两种。
- **单次出行详情**（界面 08）：地图上画出完整轨迹并标出异常位置；顶部标签汇总出行名称、偏离次数、呼叫次数；下方时间线列出出门、到达、检测到偏离、智能体提醒、家属发起呼叫、回家等事件。Demo 用系统拨号，只能记录“已发起呼叫”，无法得知是否接通。

### 5.7 记录：趋势（界面 09）

- 路线偏离周趋势：最近 8 周的偏离次数折线，以及本月合计与上月相比的变化。
- 四张指标卡，本月与上月对比（D29）：
  - 异常移动次数：本月识别出的各类异常行为次数，不论是否升级为风险；与第 3.2 节的“异常移动模式”不是一回事；
  - 导航协助次数；
  - 高风险次数；
  - 安全返回率：本月出过风险的出行中，未升级到高风险即安全回家的比例。
- 指标卡下方是一张文字卡，放智能体写的规律描述，例如“近一个月她通常周二、周四上午去菜市场”（D29）。
- 环比箭头保持黑色，与设计图一致（D29）。

### 5.8 我的（侧边抽屉，界面 01）

| 入口 | 内容 |
| --- | --- |
| 账户设置 | 姓名、头像、手机号（老人端“联系家人”与完整版外呼要用）、界面语言切换（D33） |
| 老人档案 | 姓名、称呼（用于提醒语，如“奶奶”）、照片、手机号、时区 |
| 家庭成员 | 家属列表、邀请家属、指定主要照护者、移除成员 |
| 智能体设置 | 只有一个开关：低风险时自动开启语音导航，默认开（D31） |
| 定位设置 | 安全区列表与编辑、老人手机绑定与更换、当前监测状态 |
| 通知 | 低风险、解除、监测受限三类通知的开关；高风险强提醒在 App 内不可关闭（D31） |
| 帮助 | 使用说明 |

- 抽屉顶部显示当前家属的头像、姓名与身份标识：主要照护者显示“主要照护者”，其他家属显示“照护者”。
- 抽屉底部单独一个“退出登录”按钮（界面 01）。

### 5.9 通知

| 情形 | 通知形式 |
| --- | --- |
| 低风险 | 普通通知，点开进入位置页 |
| 高风险 | 时效性通知（强提醒），点开进入事件页 |
| 风险解除 | 普通通知 |
| 监测受限 | 普通通知，说明原因（如老人手机离线）；同一次出行只推一次（D31） |

- 接收人：以上通知都发给全体已绑定的家属；完整版的自动外呼只拨主要照护者（D31）。
- 时效性通知能穿透专注模式（含勿扰），但不绕过手机的静音开关；家属也可以在 iPhone 系统设置里关掉它，这一点 App 控制不了。能绕过静音的“紧急通知”需要苹果单独审批，本项目不用。
- 通知按手机的系统语言显示中文或英文。
- 锁屏通知不显示完整坐标或轨迹。

## 6 绑定与初始设置

流程（D32）：

1. 家属在自己的 iPhone 上安装 App，选“家属身份”，用 Apple 账号登录，填写自己的手机号。
2. 家属建立老人档案，设置“家”的位置与其他安全区。
3. 家属在老人的 iPhone 上安装同一个 App，选“老人身份”，扫描家属端生成的二维码完成绑定；老人无需登录。
4. 家属代老人打开定位权限的“始终允许”与“精确位置”，以及通知权限。老人端的通知只在回家导航无法自动开始时使用，提醒老人点开导航。
5. 其他家属通过家庭成员里的邀请加入。

老人端不显示被看护状态（D11），绑定与授权由家属代办。完整版上线前，老人的知情同意需要另行设计，Demo 不涉及。

## 7 双语

## 8 完整版与 Demo 的差异

除下表所列差异外，两版相同：

| 方面 | 完整版 | Demo |
| --- | --- | --- |
| 高风险联络 | 强提醒加服务器自动外呼主要照护者 | 强提醒加事件页一键呼叫老人（D8） |
| 人数关系 | 一位家属可关注多位老人，需要切换老人的界面 | 只支持一位老人（D13、D32） |
| 异常移动模式 | 有 | 不做（D25） |
| 历史数据 | 真实使用中积累 | 开发工具按历史时间回放一个月模拟轨迹生成（D14、D41） |
| 演示方式 | 无 | 录屏 App 制成视频，汇报时播放；App 内不做演示模式（D1、D37） |

## 9 不做的事

本阶段不做：

- 安卓与网页客户端（D3）。
- App 内的演示模式（D1）。
- 老人端的看护状态显示与相关操作（D11）。
- Demo 中的服务器自动外呼（D8）。
- 医学诊断（第 1 节原则 6）。
- 两端 App 内通话；跌倒检测、手表与其他传感器；离线地图；周报与月报；上架应用商店、真实家庭试点与相应的合规认证（D33）。
