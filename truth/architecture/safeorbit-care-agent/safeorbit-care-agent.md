# 照护智能体组件图

> 承载设计文档：[工程架构](../../工程架构.md)第 5、8、9 节；本图在工程架构第 6 节末的指针表登记，边界边锚到 C2 容器图的边（写“L2 边 N”）。状态：已确认，以任务 [T4](../../../queue/tasks/T4/goal.md) 通过为准；组件划分与下文“已定的设计决定”由用户在 T4 中确认。其余依据：任务 [T2](../../../queue/tasks/T2/goal.md) 的决定 D4、D5、D9、D16、D17、D34、D35、D39。

## 视图注记

- 本系统一族（浅蓝）：本容器的组件，以及同属 SafeOrbit 的 SafeOrbit App 与照护接口；外部（灰）：云端大模型。
- 蓝虚线框“照护智能体”是本容器的边界。框内两个细虚线分组框是布局约定：“业务组件”在内圈，“技术组件”在外圈；图表引擎不能精确控位，用分组近似六边形布局。
- 底线：出行规则、异常规则、风险规则、参照路线四个规则件只做计算——输入数据，返回结果——不取数、不写数据，也不认识大模型；大模型只能经生成口被解释与对话调用。由此“风险只由规则判定”“大模型只读不写”（工程架构第 2 节原则 1、2）落成代码结构上的边界，同样的输入永远得到同样的结果，回放历史也一致。
- 照护接口给本容器的三方各开一个窄接口，不共用一个大接口：规则评估用评估上下文的读写；解释读证据、写说明；对话只得只读查询与保存对话记录，没有写风险的方法。这些接口归照护接口所有，是 D34 接受的已知取舍（风险记录经照护接口存取）；照护接口是同一系统里相对稳定的部分，所以本容器不再为它另设端口与适配器，只为供应商可替换的大模型设端口（D17）。
- 规则评估在风险变化后只发出程序内消息“风险已变化”，由解释订阅；规则评估的代码不认识解释，解释出错也不影响评估。
- Demo 中本容器是后端程序里的一个模块，各组件是模块内的子模块；边表里的“同步／异步”按完整版写，Demo 中为同进程调用。

## 组件注记

| 组件 | 类 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 规则评估 [Rule Evaluation] | 业务 | 负责编排一轮评估：取上下文，按工程架构第 8 节的处理顺序调用各规则件，把结果一次写回；不负责任何判定 | 出行规则、异常规则、风险规则、参照路线、照护接口 |
| 出行规则 [Trip Rules] | 业务 | 负责判定出行状态：过滤无效定位点，确认外出与回家，挂“监测受限”；不负责识别异常 | 无 |
| 异常规则 [Anomaly Rules] | 业务 | 负责从有效轨迹识别徘徊、长时间停留、来回折返、偏离路线，输出带证据窗口的行为观测；不负责定级 | 无 |
| 风险规则 [Risk Rules] | 业务 | 负责一位老人当前风险事件的转移（定级、升级、解除）及随转移生成的出手动作；不负责把消息送到人 | 无 |
| 参照路线 [Reference Routes] | 业务 | 负责参照路线的选用与学习：学会之前用起步规划路线，全程无风险的出行才学入常走路线；不负责判断是否偏离 | 无 |
| 解释 [Explanation] | 业务 | 负责把已判定的事实写成给家属看的说明（风险事件的经过与原因、趋势页的规律描述）；不负责判定风险 | 生成口、照护接口；订阅“风险已变化” |
| 对话 [Conversation] | 业务 | 负责回答家属提问：限定查询范围，选择只读查询，核对回答中的数字与记录编号；不负责判定风险 | 生成口、照护接口 |
| 生成口 [Generation Port] | 业务 | 负责规定本容器向大模型要什么：选择查询、生成回答、生成说明；不负责对接具体供应商 | 无（由大模型适配器实现） |
| 评估触发器 [Evaluation Trigger] | 技术 | 负责决定后台工作何时开始：评估事件到达、每 30 秒的定时检查、每天生成规律描述的时刻；不负责工作内容 | 照护接口的事件口、规则评估、解释 |
| 对话端点 [Conversation Endpoint] | 技术 | 负责对话的网络收发：校验照护接口签发的登录凭证，把回答分段送回；不负责回答内容 | 对话 |
| 大模型适配器 [LLM Adapter] | 技术 | 负责把生成口的请求经 Vercel AI SDK 交给具体供应商；不负责任何业务判断 | 生成口（实现它）、云端大模型 |

## 已定的设计决定

以下由用户在任务 [T4](../../../queue/tasks/T4/goal.md) 中确认：

- 趋势页的规律描述每天定时生成一次：评估触发器到点发起，解释写入（边 4）。
- 灌入模拟历史时，规则评估不发“风险已变化”，解释不为每次风险生成说明；灌完之后生成一次规律描述。
- 同一位老人的评估排队逐个处理（边 3），写回时由照护接口核对版本兜底（边 5）。
- 大模型失败不连累主流程：解释失败时说明留空、稍后补写；对话核对不通过时改用模板回答，或说明无法生成可靠解释（工程架构第 9 节）。
- 模块边界检查（[检查清单](../../../gate/checks.md)“模块边界检查”）在搭建后端时按本图细化：四个规则件不得引用照护接口、生成口与大模型适配器；规则评估不得引用解释；只有大模型适配器可引用 Vercel AI SDK；对话只可引用照护接口为它开的窄接口。
