# 家属登录、老人档案与手机绑定

## 来源与目的

用户明确要求开始开发家属登录、建立老人档案和绑定页面。依据 truth/产品设计.md 和 truth/工程架构.md，将现有环境骨架扩展为可保存数据、可扫码绑定的实际流程。视觉参考继续使用 reference/ui/，不改变其指向。

## 范围

- 要交付：首次身份选择；家属 Apple 登录与手机号；老人姓名、称呼、照片、手机号、时区档案；家属生成二维码、老人扫码绑定与成功界面；会话恢复与退出；对应照护接口、数据库结构和验证。
- 不包含：安全区、地图出行、风险规则、推送、智能对话和家庭成员邀请；不修改参考图与 truth；不添加假登录或 App 内演示模式。
- 允许修改的位置：object/ios/、object/server/、object/dev/；必要的 gate/checks.md 验证命令。队列工件仅由工具生成。
- Apple 账号、签名、能力配置及真机资料由用户提供；不自行操作账号或购买服务。先完成可运行代码和自动化测试，分别记录模拟器验证与真机尚未验证的事实。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 家属通过 Apple 身份验证后能保存手机号，恢复自己的会话 | 后端 HTTP 测试与 iOS 构建测试；伪造、过期及错误接收方身份凭证检查 | 有效凭证可用，无效凭证拒绝，无生产绕过登录入口 |
| A2 | 老人档案字段可以填写、保存和再次读取 | 表单校验与 HTTP 数据持久化测试 | 输入错误有提示；用户只能读写自己关联的档案 |
| A3 | 家属生成二维码，老人无需登录即可扫码完成绑定 | 二维码解析测试；接口实跑有效、过期、重复、并发领取与会话权限 | 短期一次性凭证；重复与过期拒绝；绑定结果持久保存 |
| A4 | 页面符合现有视觉风格，可切换系统中英语言，有加载和失败状态 | 模拟器构建、渲染检查与截图检查 | 页面可构建、可读、可操作；不改变 UI 参考路径 |
| A5 | 服务保持既定模块边界，新结构能用于已有数据库 | npm run check、Docker 重建与数据库迁移实跑 | 构建与测试通过，越界仍被拒绝，无删除已有数据 |

验收安排：执行者代跑终端检查并记录原样命令、退出码与输出摘录，标未独立验证；用户最终验收。真实 Apple 登录和两部真机扫码只能在签名资料与设备就绪后完成，不把模拟测试描述成真机成功。

## 执行计划

1. T6 经用户验收封存后领取本件，核对 UI 参考和现有代码。
2. 实现照护接口内的 Apple 身份验证、会话、档案存储和一次性绑定凭证；编写权限与并发测试。
3. 实现 SwiftUI 页面、照片选择、二维码生成与扫描、会话保存和中英界面。
4. 构建两端，实跑数据库迁移和绑定接口，检查页面渲染，修复问题。
5. 更新运行说明，记录真机余项，交付并同批提交，不推送。
