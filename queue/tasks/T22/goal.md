# 队列工具提速：重放时不再整份复制全部任务

## 范围

- 要交付：
  - `tool/queue_v2.py`：`legacy()` 改为逐件任务复制一层，另行复制旧版逻辑会原地修改的依赖、批准基线、回执、历史四个列表与方案；列表里的事件、基线、回执记录只读共用，不再复制。`apply()` 中的 `before` 改为只记各任务原来的状态。
  - `tool/task_queue.py`：`response_files()` 把全部任务视图生成一次供各行共用，不再每行重新生成。
  - `gate/test_task_queue.py`：新增守护测试，核对重放不改动账本事件本身、被拒绝的事件不改动既有任务状态——新的复制方式依赖这两点，日后有人改旧格式逻辑时能拦住。
  - `tool/AGENTS.md`“与模板的差异”表登记上述三个文件的改动。
- 不包含：重放结果缓存；减少每条命令的重放次数；命令、参数、输出格式与账本格式；其他规则与用法文档；与模板副本 2d423a9 的同步；`object/` 下任何文件。
- 允许修改的位置：`tool/queue_v2.py`、`tool/task_queue.py`、`gate/test_task_queue.py`、`tool/AGENTS.md`（仅差异表）。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 真实账本的重放结果不变 | 旧版与新版并排逐笔重放本仓机器账的全部事件，每笔之后比对全部任务内容、协议、配置与编号版本；最后比对全部生成视图与每件任务的就绪判断 | 每一步完全相同 |
| A2 | 只读命令输出不变 | 在本仓的临时克隆中，旧版、新版分别运行 doctor、task status（全部与单件）、task history（全部与单件）、state get、state check、config show、check --staged、repair | 标准输出、错误输出与退出码逐字节相同 |
| A3 | 写命令行为不变 | 两个临时克隆从同一提交出发，分别用旧版、新版跑同一串写操作（登记、批准、领取、改计划、交接、交付、返工、改范围、通过、让出、撤销、取消）与若干应被拒绝的输入 | 每条命令的输出与退出码相同；账本除事件时间外相同；全部任务文件逐字节相同 |
| A4 | 队列工具测试全部通过 | `/opt/anaconda3/bin/python3 -B -m unittest discover -s gate -p 'test_*.py'` | 退出码 0，含新增守护测试 |
| A5 | 明显变快 | 同一解释器在本仓运行同一组命令，记下改动前后的原样耗时 | doctor、task status、state get 各在 3 秒以内；写一笔账在 10 秒以内 |
| A6 | 改动只在授权位置 | `git diff --stat`、`git diff --check`；提交时的队列检查 | 仅授权文件；检查退出码 0 |

验收安排：A1–A6 由执行者代跑，附原样命令、退出码与输出摘录，标“未独立验证”；用户验收。
