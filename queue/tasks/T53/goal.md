# 试运行与阈值校准：用真实轨迹调整风险参数

## 范围

- 要交付（提纲）：
  - 试运行开关：打开时照护智能体照常识别异常、判定风险并记录，但不下发导航、不发通知，家属端可看到“试运行”标识。
  - 采集与分析：测试团队按场景出门（正常出行、安全区外原地站立、慢走与徘徊、绕路），用脚本统计误报与漏报，并按异常类型与参数列出。
  - 参数调整：提出调整建议，经用户确认后改后端参数，并同步工程架构第 8 节的参数表（改 truth 须用户确认）。
- 不包含：新增异常类型；真实路线学习（T44）；中文界面。
- 允许修改的位置：`object/server/` 的风险规则、参数与相关测试；`object/dev/` 的分析脚本；家属端显示试运行标识的文件；`truth/工程架构.md`（仅第 8 节参数表，经用户确认）；具体清单在批准前补全。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 试运行不打扰 | 后端用例与真机：试运行中触发徘徊 | 记录风险事件，不下发导航、不发通知；关闭后恢复 |
| A2 | 有真实读数 | 汇总测试团队的轨迹与分析脚本输出 | 各场景的误报与漏报次数有原始记录可核对 |
| A3 | 参数经确认 | 阅读参数差异与工程架构第 8 节差异 | 改动经用户确认；调整后重放同一批轨迹，读数写进回执 |
| A4 | 检查与范围 | `npm run check`；iOS 全套测试；`git diff --stat`、`git diff --check`；提交时的队列检查 | 退出码 0，无失败用例；仅授权位置 |

验收安排：执行者代跑分析与检查，标“未独立验证”；出门采集由测试团队完成。最终由用户验收。
