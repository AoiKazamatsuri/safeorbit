# 两部 iPhone 录制演示视频：最小后端与真机接入

## 范围

- 要交付：
  - 四件子任务，按顺序进行，后一件依赖前一件：
    1. 实时位置：正常出行与安全区（含设计文档改定）。
    2. 风险与提醒：低风险、高风险、风险解除、老人主动求助。
    3. 记录与趋势：出行记录、趋势（含一个月历史回放）。
    4. 智能对话。
  - 演示场景共九个：安全区、正常出行、低风险、高风险、风险解除、老人主动求助、出行记录、趋势、智能对话。
  - 本件自己的集成交付：四件子任务全部通过后，按九个场景通篇彩排，发现的问题按根契约第 16 条一次修完；把开拍前的操作步骤（启动与重置数据、服务器地址、网络、电脑防休眠、手机授权、老人手机播放轨迹）写进 `object/dev/README.md` 的“演示录制”一节。
  - 需要用户本人办理的事（不必等前一件完成，越早越好）：
    - 安装 Docker（子任务一开工时需要）；
    - 定外景路线，并拿手机实地走一遍记下轨迹（子任务一做模拟轨迹时需要；没定时先用现有样例附近的街道，定了再替换）；
    - T21 的真机复测（子任务一改位置页之前需要）；
    - 付费苹果开发者账号与推送密钥（子任务二需要）；
    - 大模型供应商与密钥（子任务四需要）；
    - 各子任务与本件的真机验收。
- 不包含：账号与绑定；多位家属与邀请；服务器自动外呼；长时间停留、来回折返、监测受限；长连接实时推送（Demo 用定时刷新）；双语（目前不做中文版）；云服务器；外景拍摄与视频剪辑本身；上架与真实家庭试点。
- 允许修改的位置：本件集成阶段只改彩排修正所需的 `object/ios/`、`object/server/`、`object/dev/` 下文件；不改 truth，确需修改时先停下问用户。各子任务的可写范围写在各自任务里。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 四件子任务全部通过 | `task status` | 四件均为“通过” |
| A2 | 自动化检查全绿 | 在 `object/server/` 运行 `npm run check`；按 `gate/checks.md` 的 iOS 检查命令跑全部测试；`-sdk iphoneos`、`CODE_SIGNING_ALLOWED=NO` 构建；制图检查 | 全部退出码 0，无失败用例 |
| A3 | 双模拟器通篇彩排 | 执行者重置数据后，用两个模拟器分别作老人与家属，老人端播放模拟轨迹，按九个场景逐一操作并截图；模拟器做不到的部分在回执写明 | 每个场景的画面与项目目标“完成的判断”一致；发现的问题已修复并重跑 |
| A4 | 开拍操作说明可用 | 阅读 `object/dev/README.md`“演示录制”一节，并按它从头操作一遍 | 按说明能从零启动到可以录制的状态 |
| A5 | 改动只在授权位置 | `git diff --stat`、`git diff --check`；提交时的队列检查 | 仅授权位置；退出码 0 |

验收安排：A1–A5 由执行者代跑，附原样命令、退出码与输出摘录，标“未独立验证”。用户安排两部真机通篇彩排，据此决定本件是否通过，也就是是否可以开拍。
