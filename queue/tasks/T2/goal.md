# 撰写 truth 三份文档：项目目标、产品设计、工程架构

## 范围

- 要交付：
  - `truth/goals.md`：按模板各节写成草稿；“文档结构”表登记新文档；“已定的方向”逐条链接本任务；“待确认事项”列齐。
  - `truth/产品设计.md`（新建）：产品定位与原则、用户与角色、核心机制（出行识别、异常行为、风险等级、分级帮助、解除、智能体分工）、老人端与家属端各页面、绑定与初始设置、双语、完整版与 Demo 的差异、不做的事、待确认事项。以 reference/ui 界面图为视觉基线。
  - `truth/工程架构.md`（新建，作为制图工具的承载设计文档）：架构原则、统一命名表、C1 系统语境图与 C2 容器图（完整版，具名 mermaid 图源，图后紧跟编号边表）、Demo 版的简化与部署（部署视图入图纸区，容器指针表以“部署型”登记）、关键流程、核心数据、规则引擎、智能体模块、客户端、实时与通知、开发与拍摄支撑、PPT 架构图初稿的修订清单、待确认事项。
  - 图纸区 `truth/architecture/`：上述各图的 SVG、可移植 SVG 与两份清单；部署视图的图源与设计说明；《治理细则》第 7 节更新本仓现状。
  - `tool/diagram/registry.json`：`settings.l2_diagrams` 登记 C1、C2 两张图名；必要时登记端点别名。
  - 状态包白名单：经 `config set` 把 `truth/产品设计.md`、`truth/工程架构.md` 加入。
  - `reference/`：保留需要的材料并在 `reference/README.md` 登记来源、日期与引用它的文档；不需要的材料移到废纸篓（可恢复）；架构图 jpg 改用可读的文件名。
- 不包含：任何代码或工程脚手架；C3 组件图；PPT 文件本身；推送远端。
- 允许修改的位置：`truth/`（含 `truth/architecture/`）、`tool/diagram/registry.json` 的 settings、`charter/config.json`（仅经 config set）、`reference/`。

### 已定的决定（成文依据）

以下为讨论中用户的决定；标“建议”的条目是执行者的建议、用户未提异议，成文后由用户审阅确认。

- D1 项目性质：Demo 级，用于课堂演示与拍摄演示视频；汇报时播放预先拍好的视频，不做 App 内演示模式。系统架构分两版：PPT 用的完整版；实际开发用的、由完整版简化而来的 Demo 版。
- D2 界面中英双语；拍摄在中国大陆。
- D3 iPhone 一个 App，按老人或家属身份切换。iOS 17 以上（建议）。
- D4 规则管判断，大模型管理解与表达，两版一致：行为识别、风险定级、出手动作只由确定性规则决定；大模型负责家属对话（经只读查询取数）、事件解释与摘要、出行规律描述；智能体对外以第一人称说话。
- D5 低风险时对老人的提醒语音用固定模板，只填称呼与地点，不经大模型。
- D6 风险分三级：正常、低风险、高风险（英文 Normal、Warning、High Risk；绿、黄、红）；“风险解除”是一次事件，解除后回到正常；定位中断另挂“监测受限”标记，不算风险等级（建议）。
- D7 低风险：老人端自动语音回家导航，同时给家属发普通通知；高风险用强提醒（建议）。
- D8 高风险联络：Demo 为家属端穿透专注模式的强提醒，加事件页一键回拨老人（系统确认后拨出），老人端“联系家人”为手动拨打；完整版为服务器自动外呼主要照护者，架构保留联络通道位置。已有或可办付费苹果开发者账号，Demo 可用远程推送。
- D9 偏离参照，两版一致：徘徊、久停、折返首日生效；路线偏离先以“家↔各安全区”的地图步行规划路线为参照，同一路线积累足够次数的正常出行后改用历史轨迹叠出的常走路线；出过风险的出行不学入；积累期间智能体状态显示学习进度。
- D10 安全区：多个带标签安全区（家、市场、医院、自定义），家必须有；安全区是熟悉地点而非围栏，离开安全区本身不算异常（建议）。
- D11 老人端不显示被看护状态，也不可操作。
- D12 家属端导航：底部三个标签（位置、智能体、记录），“我的”放进左上头像抽屉；老人身份无底部标签（建议）。
- D13 人数关系：Demo 一位老人、多位家属、一位主要照护者，一位家属只关注一位老人；完整版允许一位家属关注多位老人（建议）。
- D14 拍摄前用后端脚本灌入一个月模拟历史（开发工具，不进 App）；风险场景用 Xcode 模拟轨迹拍。
- D15 Demo 部署在开发者自己的电脑：Docker 启动后端与数据库，App 的服务器地址可配置；两部手机与电脑在同一 Wi-Fi；真人上街采集时再加内网穿透并彩排。
- D16 Demo 后端合成一个 NestJS 程序（模块化单体）：完整版的 API、智能体、实时同步三个后端容器在 Demo 中为同一程序内的模块，模块边界不变，由依赖检查把守，日后可拆；数据库 PostgreSQL 加 PostGIS。
- D17 地图用苹果自带地图（国内数据由高德提供），须处理国内坐标偏移；大模型暂不定，架构上可替换。
- D18 架构图 jpg 是初稿、未定稿；完整版以它为底稿修订，修订处逐条列给用户定。
- D19 参考资料仅供参考，只取主干；其中的具体数字、接口、表结构只作候选实现细节。
- D20 产品设计、工程架构两份文档加入状态包白名单。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| B1 | 三份文档在位，头部标“草稿”并有阅读说明 | 阅读三份文档开头 | 状态均为草稿；说明了【待确认】与“待确认事项”的用法 |
| B2 | 决定全部落文 | 按 D1–D20 逐条在文档中定位落点，列成对照表写入回执 | 每条决定都有落点，表述与决定一致；标“建议”的条目在文档中可被用户识别并确认 |
| B3 | 未定之处标记一致 | 统计每份文档正文的【待确认】与文末“待确认事项”清单，逐条对照 | 两者一一对应，无遗漏、无多余 |
| B4 | goals.md 无模板残留 | 检索模板占位语（“待”与“填写”连写） | goals.md 中不再出现模板占位语 |
| B5 | 架构图与边表一致、产物新鲜 | 依次运行渲染、可移植导出与 `tool/diagram/check.mts`；打开 SVG 目检 | 检查退出码 0、无红；SVG 可读 |
| B6 | 白名单生效 | `python3 tool/shell.py config show`；`state get` 列出的来源 | 白名单含三份文档；状态包送达三份全文 |
| B7 | 参考资料已整理 | 列出 reference/；阅读 reference/README.md | 保留的每份材料都在索引登记来源、日期与引用文档；被清理的材料在废纸篓可恢复 |
| B8 | 三份文档互相一致 | 由不共享上下文的子代理按 D1–D20 与三份文档交叉核对，报告矛盾与遗漏 | 报告中的矛盾已修正，或列为【待确认】 |
| B9 | 队列与提交检查通过 | `python3 tool/shell.py doctor`；提交时队列检查与制图提交钩子 | doctor 为 protection: ready、protocol: 2；提交被两道检查放行 |

验收安排：执行者逐项实跑并在回执中附原样命令、退出码与输出摘录；B8 由另起的子代理完成并在回执中注明；全部标“未独立验证”。用户审阅三份草稿后决定返工或通过；文档内容的“已确认”状态由用户逐份或逐节确认后另行更新。
