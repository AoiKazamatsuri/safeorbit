# 安装发布与正式推送：TestFlight 内部测试

## 范围

- 要交付（提纲）：
  - App 的 Release 配置指向云端域名；版本号与构建号规则；签名、归档、上传到 App Store Connect 与添加内部测试者的步骤。
  - 恢复推送与时效性通知能力：开发版走测试通道，TestFlight 版走正式通道。
  - 触达网关：发送失败按退避重试，有次数上限；服务器重启后补发卡住的通知；同一通知不重复送达。
  - 推送密钥只放服务器环境文件；发布步骤写进说明。
- 不包含：TestFlight 对外测试与上架；家庭与邀请（T50）；监测受限通知（T52）。
- 允许修改的位置：`object/ios/` 的签名权限、构建配置与推送相关文件；`object/server/src/outreach-gateway/` 与相关测试；`object/server/deploy/`；具体清单在批准前补全。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 可从 TestFlight 安装 | 上传构建，测试者在 TestFlight 安装 | 安装后能加入家庭并正常使用 |
| A2 | 正式通道推送 | 真机在室外经云端服务器触发低风险、高风险与解除 | 三种通知送达；高风险为时效性通知；点开进入对应页面 |
| A3 | 失败重试 | 后端用例与替身服务：发送失败、超时、服务器重启 | 按约定重试并最终送达或标记失败；不重复送达 |
| A4 | 检查与范围 | `npm run check`；iOS 全套测试；真机版本构建；`git diff --stat`、`git diff --check`；提交时的队列检查 | 退出码 0，无失败用例；仅授权位置；密钥不入库 |

验收安排：执行者代跑终端检查，标“未独立验证”；TestFlight 安装与真机推送由用户安排核对。最终由用户验收。
