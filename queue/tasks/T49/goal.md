# 云端部署：云服务器、域名与加密连接

## 范围

- 要交付：
  - 新目录 `object/server/deploy/`：生产用的 Compose 覆盖文件（复用现有后端镜像构建与 PostgreSQL 加 PostGIS），反向代理与自动申请证书（HTTPS，HTTP 一律跳转），只含变量名的环境变量样例（大模型、推送等密钥只放服务器上的环境文件，不入库）。
  - 部署脚本与说明 `object/server/deploy/README.md`：首次部署、更新、回滚；数据库每日备份、备份保留份数与恢复步骤；查看健康状态与日志的方法；后端停止或健康检查失败时能被发现的方式（至少有定时健康检查与日志记录）。
  - `gate/checks.md` 新增一节“云端部署检查”，写明检查命令与通过条件。
  - 所用的容器镜像及版本在回执列明。
- 不包含：多户、邀请与鉴权改造（T50）；App 的 Release 配置与 TestFlight 发布（T51）；对现有代码、`object/server/compose.yaml`、`Dockerfile`、`.env.example` 的修改；高可用、多机部署与负载均衡；购买服务器与域名（由用户办理）。
- 允许修改的位置：新目录 `object/server/deploy/`；`gate/checks.md`（仅新增一节）。在用户的云服务器上执行部署命令属于对外操作，领取时由用户明确授权，服务器登录凭据不写进任何记录。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 云端可用 | 按说明在用户的云服务器上从零部署；在外网运行 `curl https://<域名>/health/ready` | 退出码 0，返回数据库为 PostGIS 的就绪状态；证书有效 |
| A2 | 只走加密连接 | `curl -I http://<域名>/health/ready` | 跳转到 HTTPS 或被拒绝，不以明文返回数据 |
| A3 | 备份与恢复 | 运行备份；把备份恢复到一个新的空库并核对表与行数 | 备份文件生成；恢复后表与行数一致 |
| A4 | 更新与回滚 | 部署一个新版本，再按说明回滚 | 两次切换后健康检查均通过，数据保留 |
| A5 | 真机连通 | 一部 iPhone 关闭 Wi‑Fi、用蜂窝网络，用本机配置（不入库的 `Local.xcconfig`）指向云端域名，以演示数据选身份并上报位置；另一部看到位置 | 位置与状态正常显示 |
| A6 | 开发用法不变、密钥不入库 | 本机 `sh object/dev/compose.sh up -d --build --wait` 与 `npm run check`；`git grep` 检查密钥样式；`git diff --stat`、`git diff --check`；提交时的队列检查 | 本机启动与检查退出码 0；仓库中没有密钥值；仅授权位置 |

验收安排：云服务器与域名由用户提供；A1–A6 由执行者代跑，附原样命令、退出码与输出摘录（域名可写，服务器地址与凭据不写），标“未独立验证”。最终由用户验收。
