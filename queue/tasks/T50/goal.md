# 家庭与邀请加入：多户使用与数据隔离

## 范围

- 要交付（提纲）：
  - 后端：多户数据模型；家属新建家庭（老人称呼、手机号、时区、家的位置）；邀请码或二维码，有有效期、可作废；老人手机与其他家属凭邀请加入，令牌只在所属家庭内有效；退出家庭、移除成员、删除整户数据。
  - App：家属端新建家庭与生成邀请；老人端与其他家属扫码或输入邀请码加入；家庭成员页可用；首次使用时展示隐私说明并取得同意，高德地图的隐私确认改为在用户同意后调用（现在直接报“已同意”）。
  - 保留“预置一户人家并回放一个月模拟历史”的初始化方式，供以后录制演示使用。
  - 按根契约第 25 条写定接口约定后，后端与 App 同时施工；测试。
- 不包含：Apple 账号或手机号登录；一位家属关注多位老人；中文界面；推送与发布（T51）。
- 允许修改的位置：`object/server/`、`object/ios/`、`object/dev/` 下的相关文件与测试，具体清单在批准前补全。不改 truth，确需修改时先停下问用户。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 户间隔离 | 后端用例与接口实跑：建两户，各自上报位置、查询记录、对话与事件 | 任一户都取不到另一户的数据 |
| A2 | 未加入不可访问 | 未加入家庭的手机、已退出或被移除的手机、过期或作废的邀请码 | 取不到数据，错误码与约定一致 |
| A3 | 加入流程 | 双模拟器与真机：家属新建家庭、生成邀请，老人手机扫码或输入邀请码加入 | 加入后位置、风险与记录正常 |
| A4 | 删除与退出 | 删除整户数据；成员退出 | 数据库中该户数据清空；退出的手机回到选身份页 |
| A5 | 演示初始化照常 | 一键重置与一个月历史回放 | 演示户与历史照常生成，Demo 阶段场景不受影响 |
| A6 | 检查与范围 | `npm run check`；iOS 全套测试；真机版本构建；`git diff --stat`、`git diff --check`；提交时的队列检查 | 退出码 0，无失败用例；仅授权位置；领取前 T36 已通过 |

验收安排：执行者代跑，附原样命令、退出码与输出摘录，标“未独立验证”；真机加入流程由用户安排核对。最终由用户验收。
