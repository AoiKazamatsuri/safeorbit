# 家庭与邀请加入：多户使用与数据隔离

## 来源与目的

落地阶段总任务 [T48](../T48/goal.md) 的子任务。项目要求每户一位老人、一位或多位家属，各户只能读取与修改自己的数据。用户要求先进行 T50 开发。T36 已通过，本机后端和双模拟器可以先完成开发与自动化验证。真机验证保留在原验收范围内。

## 范围

- 多户与入门流程。首次使用展示隐私说明并取得同意后，再进入新建或加入家庭、启用定位及地图服务。家属填写自己的姓名和联系方式，填写老人姓名、称呼、联系方式、时区及家的位置后新建家庭。创建者为主要照护者。老人及其他家属通过固定邀请码或二维码加入，每户同时最多一部老人手机。成员页显示本户成员，新建家庭的主要照护者可移除成员或删除整户，其他成员可退出。邀请码不设有效期或使用次数。
- 每个设备会话绑定一个家庭及一种身份。服务器从凭据解析归属，位置、风险、出行、设置、智能体对话和触达按同一归属核对。退出、移除或删除后撤销对应设备凭据。重复或并发请求应维持一致的成员关系，已加入设备不能仅凭安装标识重新登记或换户。家属操作记到实际成员。
- 保留本机预置演示家庭与一个月历史回放。演示登记与重置须显式启用，仅能操作预置演示户。启动迁移须保留已有演示数据，普通家庭入口不能访问演示户，演示操作不影响其他家庭。整户清理走事务，覆盖家庭关联记录、设备凭据和邀请码，并保留正常风险事件的追加规则。
- 允许修改的后端文件以 `object/server/` 为根。现有 `src/care-api/{schema,database.service,care-store,care-api.module,controllers,device-auth,validation,risk-records,reset-cli}.ts`，新增 `src/care-api/{family-controller,family-store,family-validation}.ts`。如需传递实际成员身份，可改 `src/care-api/public/index.ts` 及 `src/care-agent/chat-controller.ts` 的授权接线。测试在 `test/{family,care-api,chat,records,outreach}.test.ts`。仅在 `compose.yaml` 和 `.env.example` 增加默认关闭的本机演示开关。
- 允许修改的 App 文件以 `object/ios/` 为根。现有 `SafeOrbit/{SafeOrbitApp,DemoDevice,OnboardingAPI,OnboardingStore,OnboardingModels,OnboardingUI,QRScanner,CaregiverSettings,AMapRuntime,ElderLocationReporter,RecordsAPI}.swift` 和 `SafeOrbit/Localizable.xcstrings` 的相关文案，新增 `SafeOrbit/{FamilySession,FamilyUI}.swift`，其 Xcode 工程文件只登记新增源码和测试。测试在 `SafeOrbitTests/{Family,Onboarding,DemoBackend,RecordsAPI,Location,Settings}Tests.swift`。
- 允许修改的本机工具以 `object/dev/` 为根。现有 `demo-api.mjs`、`reset-demo.mjs`、`README.md`，新增只跑本机隔离测试环境的 `check-family.mjs`。相关回放和检查沿用共享演示接口。
- 不包含 Apple 账号或手机号登录、一位家属关注多位老人、中文界面、云部署、正式推送及发布。任务记录只经队列工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
| --- | --- | --- | --- |
| A1 | 户间隔离 | 本机新建两户，分别上报位置，核对主页、出行、风险、对话查询和写入，在测试中核对按已知资源编号访问时的响应 | 两户只见各自资料，按另一户资源编号读写被拒 |
| A2 | 未加入不可访问 | 测试未入户、错误邀请码、退出、移除、重复登记和并发争用老人席位 | 未加入或已失效设备不能访问资料，合法设备身份和归属稳定，最多一部有效老人手机 |
| A3 | 加入流程与隐私同意 | 双模拟器上由家属新建和显示邀请，由老人通过邀请码加入并回放位置，另测家属加入和拒绝隐私说明。真机复验二维码扫描及实际定位 | 加入后位置、风险与记录正常，拒绝同意时不开始定位，不初始化高德，也不进入家庭流程 |
| A4 | 退出、移除与删除整户 | 运行家庭管理接口与 App 流程，核对旧凭据失效和数据库关联行，核对另一户数据 | 操作权限按成员类型核对，家庭数据可完整删除，已退出或移除的手机回到选身份页，另一户数据保持完整 |
| A5 | 演示初始化照常 | 在明确开启的本机演示环境运行一键重置及一个月历史回放，核对另一户数据与自动化回归 | 演示户与历史成功生成，常规模式拒绝演示登记与重置，重置不会清理其他家庭 |
| A6 | 检查与范围 | `npm run check`，`node object/dev/check-family.mjs`，`sh object/dev/ios-check.sh`，通过 `-sdk iphoneos CODE_SIGNING_ALLOWED=NO` 编译，差异与暂存队列检查 | 退出码 0，无失败用例，改动在授权范围内，T36 已通过 |

验收安排：执行者先在本机及模拟器执行全部可代跑检查，真机摄像头扫描、定位和加入复验保留给具备装机条件后的验证。回执记录原样命令、退出码、读数、模拟器与真机覆盖范围，标明未独立验证。用户决定最终通过。

## 执行计划

1. 核对远端任务账。依本次授权，工作及提交先留本地，GitHub 推送权限恢复后再同步。按用户确定的顺序更新 T48 的执行次序，修订 T50，保留 T36 作为前置，批准并领取。
2. 根据现有代码用 `task replan` 固定后端与 App 共用的接口约定。约定包括创建、加入、成员列表、退出、移除、删户与会话恢复的请求及回复示例，凭据身份，错误码，演示入口和现有推送载荷及本地化键的兼容。实现前明确失败重试、并行加入、旧设备撤销和会话恢复场景。
3. 后端和 App 按同一份约定并行施工，各自运行替身测试。后端先补齐持久化、权限和演示隔离。App 复用入门表单、扫码组件和钥匙串，在登录态失效时回到选身份页并清理原户数据。合入后连本机后端做一次完整联调。
4. 使用独立测试库和两台模拟器完成本机验收，保留真机复验记录。按任务规则登记回执并同批提交。本轮提交先留本地。
