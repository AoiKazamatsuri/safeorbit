# 子代理推理等级统一为 High

## 来源与目的

用户明确指令：以后子代理统一用 High 推理等级。现状：根契约第 21 条只在“判断、架构或高风险决策的评审”一行写了“最高推理档”，其他任务形态没有写推理等级；任务 T27 派发施工子代理时没有指定推理等级，按本机 Claude Code 全局设置运行（设置为 xhigh）。按 charter 契约“修改常设规则”，常设规则的变更经任务记录依据后写进根契约，使以后接手的执行者读到同一要求。

## 范围

- 要交付：根契约第 21 条——表中“判断、架构或高风险决策的评审”一行去掉“最高推理档”；表后说明补一句：子代理的推理等级统一用 High，不分任务形态，也不随派发它的会话自身的档位；Claude Code 派发时把 Agent 工具的推理等级设为 high，Codex 用对应的 high 档。
- 不包含：模型型号的选派（仍按第 21 条表格）；已经派出、正在运行的 T27 施工子代理（不中途重派）；本机 Claude Code 全局设置；其他条款。
- 允许修改的位置：`AGENTS.md`（仅第 21 条）。队列记录只经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 第 21 条写明统一用 High | 阅读差异 | 表中不再有“最高推理档”；表后写明统一用 High 及两种执行者的设法；其他条款不变 |
| A2 | 全仓没有相冲突的说法 | `git grep -n -e '推理档' -e '推理等级' -- ':!queue/tasks' ':!.shell' ':!object'` | 只剩第 21 条新写的说法 |
| A3 | 改动只在授权位置 | `git diff --stat`、`git diff --check`；提交时的队列检查 | 仅 `AGENTS.md`；检查退出码 0 |

验收安排：A1–A3 由执行者代跑，附原样命令、退出码与输出摘录，标“未独立验证”。最终由用户验收。

## 执行计划

1. 写账前比对远端，登记并批准、领取。
2. 执行者改第 21 条，跑 A2、A3。
3. 写回执交付，同批提交并推送；等用户验收。
